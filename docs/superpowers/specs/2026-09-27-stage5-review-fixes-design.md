## 1. 地図に渡す住所から建物名を外す(最優先1)

- 事実: 「神奈川県横浜市中区山下町279 グランドコート横浜レジデンス棟1203号室」を Googleマップに渡すと、別の建物(山下町31)が目的地になった。`googleMapsUrl.ts` が住所をそのまま渡しているため。
- 直し方: Googleマップ用の URL を作るときだけ、住所から建物名・部屋番号を外す純粋な関数 `addressForMaps(address)` を足す(新しいファイル `src/addressForMaps.ts`)。保存する住所・画面の表示・CSV/バックアップは変えない。位置が登録済みの地点は今までどおり座標を渡す(`pointOf`)。
- 外すのは「はっきり見分けられるとき」だけ:
  1. 番地(数字と `-` `－` `ー` `−` `‐` `丁目` `番地` `番` `号` の並び、全角数字も)の直後に空白(半角・全角)があり、その後ろに文字が続く → 空白から後ろを外す。
  2. 番地の直後(空白なし)に、`号室`・`階`・`F`・`棟`・`号棟` を含む部分が続く(例: `1-2-3-405号室`、`1-2-3 5F`、`1-2-3A棟`)→ その部分を外す。
  3. 上に当てはまらない形(番地が見つからない、建物名が番地より前にある等)は何もしない。
- テスト: 上の例、空白なしの建物名(`山下町279グランドコート` は外さない=迷う形)、番地が無い住所、`丁目` 表記、全角の数字と空白、外した結果が空にならないこと。
- URL の組み立て(`buildGoogleMapsUrl`)は住所の配列を受け取るまま。呼び出し側(ルートの地点を作る所、`pointOf` の住所の枝)で `addressForMaps` を通す。1件だけの地点検索にも使う。

## 2. iPhone のホーム画面追加の案内(最優先2)

- 事実: iPhone では Safari とホーム画面のアプリでデータの置き場所が別。Safari で登録してから追加すると、アプリは空で開く。Safari 側のデータは7日使わないと消えうる。
- 追加前: iPhone(iPadを含む)の Safari で、登録済みの訪問先が1件以上あるとき、ホーム画面追加の案内(`installHint`)の手順の最初に「1. 設定 → バックアップを書き出す(写真も含める)」を入れ、以降の番号を1つずらす。最後に「追加したアプリを開いたら、設定の『読み込む』でこのファイルを読み込んでください」を足す。
- 追加後: ホーム画面から開いた iPhone のアプリ(`navigator.standalone` または `display-mode: standalone`)で、訪問先が0件、かつこの案内をまだ閉じていないとき、一覧の上に案内カードを出す。
  - 文: 「Safari で使っていた場合は、書き出したバックアップのファイルを読み込むと、今までの訪問先が入ります。」
  - ボタン: 「読み込む画面へ」(設定の画面を開き、バックアップの欄が見えるようにする)/「閉じる」(localStorage に閉じたことを記録。以後出さない)
- 端末の判定は薄い層(既存の `platform` 系の関数、無ければ `src/platform.ts`)にまとめ、テストでは差し替える。

## 3. バックアップの「今のデータに追加する」(最優先3)

- 事実: 追加(merge)で、ファイルにいる人は手元に同じ id がいても上書きされ、位置・メモ・許可証の期限が古い内容に戻る。事業所・出発帰着も上書きされる。
- 直し方:
  - 訪問先: 手元に同じ id が**いない**人だけ追加する。手元にいる人は何も変えない。
  - 写真: 新しく追加した人の写真だけ入れる(1人3枚まで)。
  - お役立ち地点: 手元に同じ id がいない地点だけ追加する。
  - 事業所・出発帰着(meta): 手元が未設定のときだけ入れる。
  - 確認の文: 「N人を追加します(手元にいるM人はそのまま)。よろしいですか?」。M=0 のときは括弧を書かない。N=0 のときは確認を出さず「追加する訪問先はありませんでした(手元にいるM人はそのまま)。」とだけ出す。
  - 終わりの文: 「N人を追加しました。」(地点があれば「・お役立ち地点K件」)
- 入れ替え(replace)は今までどおり(全部をファイルの内容にする)。ただし第5章の「一続きの書き込み」にする。

## 4. データベースのつながり(最優先7)

- 事実: `db.ts` の接続は一度作ると作り直さない。iPhone では、バックグラウンドから戻ったときに接続が切れる既知の不具合があり、そのあと保存がすべて失敗する。最初の接続の失敗も覚えたままになる。
- 直し方(`src/db.ts`):
  - `openDB` に `terminated`(接続が切れた)→ 覚えている接続を捨てる、`blocking`(新しい版のアプリが更新を待っている)→ 接続を閉じて捨て、ページを読み直す、を渡す。`blocked` は何もしない(相手が閉じるのを待つ)。
  - 最初の接続が失敗したら、覚えている Promise を捨てる(次の操作で作り直す)。
  - 読み書きの関数は共通の包み(`withDb`)を通し、`UnknownError`・`InvalidStateError`(接続が閉じている)のときは接続を作り直して**1回だけ**やり直す。
- 見えない失敗をなくす: 「済」の記録(履歴への書き込み)が失敗したときは、黙らず「訪問の記録を保存できませんでした。」を出す。

## 5. 一続きの書き込み(中: 読み込みの途中失敗)と写真の掃除(小さいが同じ所なので含める)

- バックアップの読み込み(入れ替え・追加)と引き継ぎの受け取りは、訪問先・写真・お役立ち地点・設定(meta)を **1つのトランザクション** で書く。途中で失敗したら何も変わらない。写真の Blob は書き込みの前に全部作っておく(今もそうしている)。入れ替えのときは、同じトランザクションの中で写真を空にしてから入れる。
- `db.ts` に、まとめて書く関数(例 `applyImport(plan)`)を1つ足し、`backupFlow`・`transferReceive` はそれを呼ぶ。失敗のメッセージは今の文のまま、ただし「途中まで入った」前提の読み直しは不要になる(読み直し自体は害がないので残してよい)。
- 訪問先を削除するとき(1人・まとめて)、その人の写真も同じトランザクションで消す。
- 起動したとき、持ち主のいない写真を消す(`deleteOrphanPhotos` を起動時に1回、画面の表示を待たせない)。

## 6. 自動更新で入力が消える(中)

- 事実: 新しい版が公開されると、起動して数秒後に無条件で読み直され、入力中の登録や取り込みが消える/切れる。
- 直し方: `swUpdate.ts` で読み直しを直接させず、「今は読み直してよいか」を main.ts に問い合わせる。次のどれかの間は待たせる: 登録・編集の画面、小窓(dialog)を開いている、書き込み中(読み込み・受け取り・送るの `working`)。待たせた後は、その状態が終わったとき(`setState` の中で判定)に読み直す。
- 読み直しを待っていることは画面に出さない(次に一覧に戻ったときに読み直される)。
- vite-plugin-pwa の仕組み上、読み直しを差し止められない場合は、`registerType` を `prompt` 相当にして、自分で `updateSW(true)` を呼ぶ形に変えてよい(実装時に確かめる)。

## 7. バックアップの書き出し(中)

- 事実: 画面が持っている一覧を書き出すので、起動時の読み込みに失敗していると空のバックアップができ、「最後のバックアップ」も更新される。iPhone のホーム画面アプリでは、ダウンロードの保存が不安定。
- 直し方:
  - 書き出すときはデータベースから読み直す(訪問先・写真・地点・設定)。読めなかった、または訪問先が0件なら書き出さず「書き出す訪問先がありません。」/「データを読めなかったので書き出しませんでした。」を出す。
  - 2段階にする(第11章の「送る」と同じ形): 「書き出す」でファイルを作る → 「保存する」ボタン(共有できる端末では共有画面。iPhone は「"ファイル"に保存」を選べる)。共有できない端末ではダウンロードし、保存先を案内する。
  - 「最後のバックアップ」を記録するのは、共有が終わったとき・ダウンロードを始めたときだけ。共有を取り消したときは記録しない。

## 8. 経由地の数(中)

- 事実: 「現在地から」のとき、1ルート10件はすべて経由地+目的地になり、経由地が9か所になる。実機で確かめたのは8か所まで。
- 直し方: 出発が「現在地から」のルートでは、1ルートの上限を9件にする(`MAX_STOPS_PER_ROUTE - 1`)。ルートの分け方(`routeSplitter`/`routePlan`)にこの条件を渡す。画面の「1ルート10件まで」の説明は、現在地からのとき「9件まで」と出す。

## 9. 引き継ぎの「上書き」で手元の項目が消える(中)

- 送り手の記録で、電話・位置・駐車・許可証の期限・メモが空(未設定)の項目は、手元の値を残す。名前・住所は送り手の値。写真は今の決まり(受け取った写真が0枚なら手元を残す)のまま。
- `transfer.ts` の `planImport` で行う。テストを足す。

## 10. パスワードの強さ(中)

- `MIN_PASSWORD_LENGTH` を 10 にする(送るときのパスワード・事業所の合言葉の保存)。
- 新しく作るファイルの反復回数 `PBKDF2_ITERATIONS` を 600,000 にする。ファイルに回数が書いてあるので、20万回で作った今までのファイルもそのまま開ける(上限 200万の範囲)。
- 保存済みの合言葉が10文字未満のとき: 受け取りでは今までどおり自動で試す。送るときは「事業所の合言葉が短いので、10文字以上に変えてください。」を出し、合言葉を使うチェックを外してパスワード入力にする。設定の合言葉の欄にも「10文字以上に変えてください」を出す。
- 画面の説明: 「10文字以上。言葉をつなげると覚えやすくなります(例: さくら訪問2026秋)」。

## 11. 「送る」を2段階に(最優先6)

- 事実: 共有画面(`navigator.share`)は「押した直後」でないと開けない。今は確認の小窓・写真の変換・暗号(時間がかかる)を挟んでから開くので、共有にならずダウンロードになる恐れがある。保存先の案内もない。
- 直し方:
  - 送る小窓の流れ: `form`(パスワード等)→「ファイルを作る」→ `working`(「ファイルを作っています…」)→ `ready` → 共有/保存 → `done`。
  - `ready` の画面: 共有できる端末(`navigator.canShare({files})` が真)では「LINEなどで送る」ボタン。押した処理の中で、すでに作ってある File を直接 `navigator.share` に渡す。共有できない端末では「ファイルを保存」ボタン(ダウンロード)と、保存先の案内(iPhone:「ファイル」アプリの「ダウンロード」、Android:「ダウンロード」、パソコン: ダウンロードのフォルダ)。
  - 共有を取り消したときは `ready` に戻る(もう一度押せる)。
  - 送る前の `window.confirm` はやめる(小窓に注意書きがある)。
  - 作ったファイル(File)は flow の中に持ち、state には入れない。小窓を閉じたら捨てる。
- 型: `TransferSendDialog.phase` に `'ready'` を足す。

## 12. 縦に長い小窓(最優先4)

- `.sheet` に `max-height: calc(100dvh - 2rem - env(safe-area-inset-top) - env(safe-area-inset-bottom))`、`overflow-y: auto`、`overscroll-behavior: contain`。`dvh` が無いブラウザ向けに `vh` の指定を先に置く。
- 開いたとき、初期フォーカスの要素が見える位置にスクロールされること(ブラウザの既定で足りるか確かめる)。
- 確認: 375×667・667×375(横向き)・320×568 で、送る(合言葉なし)・位置の登録(貼り付けを開いた状態)・受け取りの同じ人の画面の一番上と一番下に届く。

## 13. 地図の画面で名前が見えなくなる(最優先5)

- 地点の行(`routeMapView.ts` の `li`)を折り返せるようにし、名前の欄に最小幅(例 `min-width: 8em` 相当、ただし画面より広くしない)を持たせる。ボタン(☎・写真・位置・済)が入りきらないときは名前の下の2段目に回る。
- 確認: 320px・375px で、長い名前・☎・写真あり・済 HH:MM の状態でも名前が1行以上の幅で見える。はみ出さない。

## 14. 「全解除」と「先週と同じ」の元に戻す(最優先8)

- 検索中(一覧が絞り込まれているとき)の「全解除」は、**見えている行だけ**選択を外す。ボタンの表示(全選択/全解除)の判定も見えている行で行う(今と同じ)。
- 「全解除」と「先週の○曜日と同じ」(と「履歴から選ぶ」で今の選択を置き換える操作)は、確認なしで実行し、直前の選択と順番を覚えておく。下に知らせ(既存の削除の「元に戻す」と同じ見た目)を出す:
  - 「選択を外しました」「選択を置き換えました」+「元に戻す」
  - 「元に戻す」で、覚えておいた選択と順番(と開いたルートの記録)を戻す。
  - 知らせは、次に選択を変える操作をするか、画面を移ると消える。
- 選択を外す前が0件のとき(何も失われないとき)は知らせを出さない。

## 15. 戻るボタン(最優先9)

- 画面を移るとき(一覧→訪問順→地図、一覧→登録・編集、一覧→設定、履歴など)と、小窓を開くときに `history.pushState` で記録を積む。`popstate`(戻る)で:
  1. 小窓が開いていれば閉じる(`closeAnyDialog` と同じ。`working` 中は閉じずに記録を積み直す)。
  2. 登録・編集の画面なら「キャンセル」と同じ動き(入力中なら「入力中の内容を捨てますか?」、いいえなら記録を積み直してとどまる)。
  3. それ以外の画面なら、1つ前の画面に戻る(アプリの中の「戻る」と同じ)。
  4. 一覧で何も開いていなければ、何もしない(ブラウザの既定どおりアプリを出る)。
- アプリの中の「戻る」「キャンセル」「閉じる」ボタンで画面や小窓を閉じたときは、積んだ記録を1つ取り除く(`history.back()` を使うか、記録の数を数えて合わせる。二重に戻らないこと)。
- 地図(Googleマップ)から戻ってきたときの動き(選択と順番の復元)は変えない。
- テスト: jsdom で `popstate` を送って確かめる。

## 16. 画面を移ったら一番上から(中、端末テストで発見)

- 画面(`state.screen.name`)が変わった描き直しのときだけ `window.scrollTo(0, 0)` する。同じ画面の描き直し(選択・入力・GPS 更新など)ではスクロール位置を動かさない。
- 戻るで前の画面に戻ったときも一番上でよい(一覧の位置の記憶は今回しない)。

## 17. 一覧の高さ(中)

- 選択バーを1段にする: 「N件選択中」・「⋯」・「訪問順を決める →」。「⋯」を押すと小さな小窓(既存の行メニューと同じ形)で「送る」「削除」を出す。`--selbar-h` は1段の高さに戻し、狭い画面の2段の指定(30rem 以下)は外す。
- 一覧の上: 画面に残る(sticky)のは検索欄の行だけにする。見出し・履歴から選ぶ・登録ボタン・並び替え・すべて/選択中の切り替えは一緒にスクロールする。
- 確認: 375×553・320×568 で、1人以上選んだ状態で一覧に2行以上見える。

- 純粋な関数(`addressForMaps`、追加の計画、上書きの項目の残し方、ルート上限9件)は Vitest で先に書く。
