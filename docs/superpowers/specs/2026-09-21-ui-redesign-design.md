# 訪問ルート作成 UI/UX 改善 設計書

作成日: 2026-09-21

前提となる設計書: `2026-09-02-route-auto-input-design.md`。本書は**画面構成・見た目・文言・操作**を改める。保存の仕組み、Googleマップとの連携ロジック、ルート分割、PWAの仕組みは変えない。

## 1. 目的と方向性

薬局・医療・介護など特定の業種向けではなく、**「複数の行き先を選び、訪問順を決めて、地図アプリでルートを開く」**誰でも使える汎用のルート作成アプリにする。初めて開いた人が、説明書なしで「何をすればよいか」を理解できることを最優先にする。

操作は3ステップに統一する。

1. 訪問先を選ぶ
2. 訪問順を決める
3. 地図で開く

## 2. 決定事項(ユーザー承認済み)

| # | 決定 |
|---|---|
| 1 | 「複数端末での運用」(統合・更新者・暗号化バックアップ)は**今回は見送る**。作業済みの内容は`feature/multi-device-sync`ブランチに残す |
| 2 | 並べ替えは**▲▼のみ**。ドラッグ&ドロップは実装しない(iPadの実機で確認できないため) |
| 3 | 削除の確認は、標準のダイアログではなく**自前のダイアログ**にする(ボタンの文言と赤色を指定するため) |
| 4 | 未着手のルートは灰色、次に開くルートは青、開いたルートは緑。**赤は削除と警告だけ**に使う |
| 5 | 開いたルートには**開いた日時**も表示する(端末内の一時的な記録に日時を足す) |
| 6 | 文字と背景の明るさの差は、標準的な基準(通常の文字で4.5:1以上)を満たす |

## 3. 制約

- **保存形式を変えない。** IndexedDBの構造、バックアップファイルの形式は変更しない。既存の登録データは何もせずにそのまま読める。移行処理は不要。
- 訪問先のデータを外部サーバーへ送信しない。ネットワーク通信は、ユーザーが押した「地図で開く」の遷移だけ。
- 氏名・住所を`console`へ出力しない。例外メッセージにも含めない。
- 実行時依存は`idb`のみ。UIの部品ライブラリを追加しない。
- 既存のPWAの仕組み(マニフェスト、Service Worker、standalone表示)を壊さない。
- 訪問順の自動最適化はしない。ユーザーが決めた順番を保つ。
- 既存機能(検索、選択、並べ替え、ルート分割、Googleマップ連携、選択の復元、書き出し・読み込み)を壊さない。

## 4. 用語

画面上の文言から、業種特有の表現をなくす。**内部の識別子(`Patient`型など)は変えない**(保存形式と無関係で、変更の影響が大きいため)。

| これまで | これから |
|---|---|
| 患者 | 訪問先 |
| 患者を登録 | 訪問先を登録 |
| 氏名 | 名前 |
| 次へ(順番を決める) | 訪問順を決める → |
| Googleマップで開く(1本のとき) | この順番で地図を開く → / Googleマップで開く |

「薬局」「在宅」「医療」「利用者」も画面に出さない。READMEの利用者向けの説明も同じ用語に直す。

### アプリ名の一元管理

仮の名称は**「訪問ルート作成」**。`src/appInfo.ts`に`APP_NAME`を1か所だけ定義し、次のすべてがそこから決まるようにする。

- 画面の見出し
- `index.html`の`<title>`と`apple-mobile-web-app-title`(ビルド時に置き換える)
- PWAのマニフェストの`name`と`short_name`(`vite.config.ts`が読む)

※すでにホーム画面に追加済みの端末では、アイコンの名前は、追加し直すまで古いままになる。

## 5. 画面構成

```
訪問先を選ぶ ⇄ 訪問順 ⇄ 地図を開く      (下部のタブで移動)
        ↘ 訪問先の登録・編集(全画面)
        ↘ 設定(右上の歯車)
```

`Screen`は`list` / `form` / `order` / `map` / `settings`の5つ。`map`を新しく足す。

### 5.1 下部のタブ(ステップ表示を兼ねる)

- `list`・`order`・`map`の下部に固定表示する。`form`と`settings`では出さない。
- 3つのタブは「① 訪問先を選ぶ」「② 訪問順」「③ 地図を開く」。**番号付き**で、今の画面を強調し、`aria-current="step"`を付ける。これが仕様のステップ表示になる。
- 訪問先を1件も選んでいないときは、②③のタブを押せなくする(`aria-disabled`、薄い表示)。
- ②③のタブは、選んだ順序をそのまま使う。②を通らずに③へ進んでも、その時点の順序で地図を開ける。

### 5.2 訪問先を選ぶ(`list`)

上から順に、次の要素を並べる。

1. **見出しの行**: アプリ名(左)、設定の歯車ボタン(右)。上部に固定する(sticky)。
2. **検索欄**: プレースホルダー「名前・住所で検索」。名前・住所のどちらでも部分一致で、入力中に絞り込む。文字があるときだけ、右端に**クリアボタン(×)**を出す。押すと消して、検索欄にフォーカスを戻す。現在のIME変換中の扱い(変換が確定してから絞り込む)は維持する。
3. **登録ボタン**: 全幅の青いボタン「＋ 訪問先を登録」。
4. **一覧**: 各行は次の構造。
   - 行全体をタップして選択・解除できる(`<label>`が`<input type="checkbox">`を包む。本物のチェックボックスなので、キーボードとスクリーンリーダーでも操作できる)
   - 名前(太字)、住所(灰色、最大2行で省略)
   - 右端に「⋯」ボタン(行のタップとは独立。タップしても選択は変わらない)
   - **選択状態**は、チェックマーク、薄い青の背景、左の青いライン(4px)の3つで示す(色だけに頼らない)
   - 上限(10件)に達したら、未選択の行は選べなくなり、理由を一覧の上に表示する
5. **0件の表示**: 登録が0件なら「まだ訪問先が登録されていません。「＋ 訪問先を登録」から追加してください。」。検索の結果が0件なら「該当する訪問先がありません」。
6. **選択バー**: 1件以上選んでいるとき、タブの上に固定表示する。「3件選択中」と、青いボタン「訪問順を決める →」。0件のときは出さない。
7. 一覧の最後は、選択バーとタブに隠れない余白(safe-areaを含む)を取る。

### 5.3 「⋯」メニューと削除の確認

「⋯」を押すと、下からのシート(ダイアログ)を出す。

- 見出し: その訪問先の名前
- ボタン: **編集** / **複製して登録** / **削除**(赤) / **キャンセル**
- **複製して登録**: 名前と住所を写した状態の新規登録フォームを開く。保存すると別の訪問先として登録される
- **削除**を押すと、続けて確認のダイアログを出す。「この訪問先を削除しますか?」と名前を表示し、[キャンセル]と[削除(赤)]。**削除の実行は必ずこの確認を通す。**
- どちらのダイアログも次を守る: `role="dialog"`、`aria-modal="true"`、見出しで名前を付ける。開いたら最初のボタンにフォーカスを移し、閉じたら開いた元の「⋯」に戻す。Escキーで閉じる。背景の外側を押しても閉じる。背後のスクロールは止める

### 5.4 訪問先の登録・編集(`form`)

- 上部の行: 左「キャンセル」、中央「訪問先を登録」または「訪問先を編集」、右「保存」。
- 入力欄は**名前**と**住所**の2つ。どちらも必須と表示する。住所が空、または名前が空のときは保存できない(押すとエラーを表示して保存しない。現在の動作を維持する)。
- 保存に失敗しても、入力内容を画面に残す(現在の動作を維持する)。
- 「この住所をGoogleマップで確認」のリンクを、住所欄の下に維持する。

### 5.5 訪問順(`order`)

- 上部の行: 左「‹ 戻る」(訪問先を選ぶへ)、中央「訪問順を決める」。
- **縦につながった一覧**で、各行に大きな番号の丸(①②③…)、名前、住所、▲▼ボタンを並べる。番号の丸は縦の線でつなぐ。
- 先頭の行に**START**、最後の行に**GOAL**のバッジを付ける。
- 選択が1件だけのときは、START/GOALを出さない。「1件だけのときは、その場所を地図で開きます」と案内する。
- ▲▼は44px以上。先頭の▲、末尾の▼は押せなくする。並べ替えの結果は行の並びと番号にすぐ反映する。
- 「＋ 訪問先を追加」(訪問先を選ぶへ戻る)、並べ替えの案内文、同じ住所が複数あるときの警告(現在の動作を維持する。ブロックしない)。
- 主要ボタン「**この順番で地図を開く →**」(地図を開くの画面へ)。

### 5.6 地図を開く(`map`)

- 上部の行: 左「‹ 戻る」(訪問順へ)、中央「地図を開く」。
- **概要**: 「9件の訪問先が選択されています。」。ルートが2本以上に分かれるときは、続けて「2つのルートに分割します。1つのルートは最大5地点までです。上から順に開いてください。」(5は`MAX_STOPS_PER_ROUTE`から出す。数字を直に書かない)。
- **ルートのカード**(1本のときも同じ形):
  - 見出し「ルート1」、地点数「5地点」、名前を「山田 → 鈴木 → …」でつないだ表示
  - **開いたルート**(緑のカード): 「✓ Googleマップで開きました」と開いた日時(例: 9/21 14:32)。小さめの「もう一度開く」ボタン
  - **次に開くルート**(青の枠・青い背景、最も目立たせる): 「次に開く」のラベルと、大きな青いボタン「Googleマップで開く」。最初の未開封のルートがこれになる
  - **それ以降のルート**(灰色のカード): 通常のボタン「Googleマップで開く」
  - すべてのルートは、状態にかかわらず、いつでも開ける
- 1つのルートしかなければ、そのカードが「次に開く」または「開きました」になる。
- 選択が0件のときは「訪問先が選ばれていません」と、「訪問先を選ぶ」ボタンを出す。
- 「開いたルートの印」は、訪問順が変わるか、訪問先を選び直したときに消す(現在の動作を維持する)。

### 5.7 設定(`settings`)

- 上部の行: 左「‹ 戻る」、中央「設定」。
- **現在の機能をそのまま残す**: 書き出し、読み込み(入れ替え/追加の選択を含む)、登録件数の表示。文言だけ「訪問先」に直す。見た目は他の画面に合わせて整える。

## 6. 地図サービスとの連携の分離

- `src/mapProviders.ts`を新しく作り、地図サービスを次の形で表す。

```ts
type MapProvider = {
  id: string;                                       // 'google'
  label: string;                                    // 'Googleマップ'
  buildUrl(addresses: readonly string[]): string;   // 1件なら検索、2件以上なら経路
};
```

- 実装するのは**Googleマップだけ**。既存の`buildGoogleMapsUrl`(URL生成)をそのまま使い、`googleMapsProvider`として包む。
- UIは`MapProvider`だけを知り、ボタンの文言(「〇〇で開く」)は`label`から作る。Apple Mapsなどは、この型に実装を足すだけで対応できる形にする(今回は追加しない)。
- 遷移(`window.location.href`)は、今までどおり`openRoute.ts`に置く。

## 7. 開いたルートの記録

- 端末内(`localStorage`)の一時的な記録に、開いた日時を足す。氏名・住所は含めない。有効期限(12時間)も変えない。

```ts
type SessionRecord = {
  selectedIds: string[];
  /** 開いたルートの番号と、開いた日時(ISO 8601)。日時が不明な古い記録は '' */
  opened: { index: number; at: string }[];
  timestamp: string;
};
```

- 古い形式(`openedRouteIndexes`だけ)の記録も読める(日時は空として扱い、日時を表示しない)。
- 選択の復元で開き直したときは、**開いたルートが1つでもあれば地図の画面**、なければ訪問順の画面から始める(Googleマップから戻ってきたとき、次に開くルートがすぐ分かるようにするため)。

## 8. デザイン

### 8.1 色(CSSの変数として1か所に定義)

| 用途 | 色 | 用途の例 |
|---|---|---|
| 背景 | `#f5f7fa` | アプリ全体の背景。カードは白 |
| 文字 | `#1f2328` | 通常の文字 |
| 補助 | `#5f6368` | 住所、案内文 |
| 境界線 | `#d8dce1` | |
| メイン(青) | `#0b57d0` | 主要ボタン、選択、次に開くルート |
| 薄い青 | `#e8f0fe` | 選択した行の背景 |
| 完了(緑) | `#187a34` / 薄い緑 `#e6f4ea` | 開いたルート |
| 削除・警告(赤) | `#c5221f` / 薄い赤 `#fce8e6` | 削除、警告 |

文字と背景の組み合わせは、すべて4.5:1以上。ボタンの枠など文字でない部品は3:1以上。テストで、変数の値から実際に計算して確かめる。

### 8.2 形と大きさ

- 角丸: カード・ボタン・入力欄は10px、シートは12px。
- 文字: 本文は16px。補助の文字も14px未満にしない(今ある12pxの表示は14px以上に直す)。入力欄は16px以上(iOSのSafariで、入力時に画面が拡大されるのを防ぐ)。
- タップ領域は44px以上。主要ボタンは52px。
- 余白は広めに、情報を詰め込まない。影や動きなどの装飾は使わない。

### 8.3 レスポンシブ・safe-area・PWA

- 内容の幅は最大704px(44rem)で、中央に寄せる。固定の下部バー(選択バー・タブ)は背景を画面幅いっぱいにし、中身を同じ幅に揃える。
- 375px、768〜1024px、1280px以上のそれぞれで崩れない。iPadの横向きでも崩れない。
- `viewport-fit=cover`は現状のまま。上部は`env(safe-area-inset-top)`、下部の固定バーは`env(safe-area-inset-bottom)`、横向きの左右は`env(safe-area-inset-left/right)`をpaddingに足す。ホームインジケータと下部のボタンが重ならない。
- standalone表示、マニフェスト、Service Workerは変えない(名前だけがアプリ名の一元管理で変わる)。

### 8.4 アクセシビリティ

- 状態を色だけで示さない(選択はチェックマーク、完了は「✓ 開きました」の文字)。
- フォーカスの表示を消さない。`:focus-visible`で3pxの青い枠を出す。
- チェックボックスなどはキーボードで操作できる。ボタンの`aria-label`は、押す対象が分かる文にする(例:「山田 太郎のメニューを開く」)。
- メッセージ領域は`role="status"`(現状維持)。タブは`<nav aria-label>`。

## 10. テスト

### 自動テスト

- 既存の文言・構造に依存するテストを、新しい画面に合わせて直す(件数が減らないこと)。
- 行全体のタップで選択・解除できる。「⋯」を押しても選択は変わらない。
- 選択状態が、チェック、背景の印、左のライン(のクラス)の3つで示される。
- 検索: 名前・住所のどちらでも絞り込む。クリアで元に戻る。0件の表示。
- 下部の選択バー: 0件で出ない、1件以上で出る、件数が正しい。
- 「⋯」メニューの4つのボタン。削除は確認を通らないと実行されない。複製で名前と住所が写った新規フォームが開く。ダイアログのフォーカス移動、Escキーで閉じる。
- 訪問順: START/GOALの位置、番号、▲▼の端の無効化、1件のときの表示。
- 地図: ルートのカードの数と内容、次に開くルートの判定、開いたルートの表示と日時、上限の数字が`MAX_STOPS_PER_ROUTE`から出ること、選択0件の表示。
- 地図サービス: `MapProvider`経由で今までと同じURLが作られる。
- 開いたルートの記録: 日時の保存と復元、旧形式の読み込み、復元後の開始画面(開いたルートの有無で地図/訪問順)。
- アプリ名: `index.html`とマニフェストが`APP_NAME`から決まる。画面に「患者」「薬局」「在宅」「医療」「利用者」が出ない(文言の一覧を検査)。
- 色: 変数の組み合わせのコントラスト比が基準以上。
- 既存の保存データ(バージョン1のデータベース)が、そのまま読める。

### 私が行う画面の確認

ビルドした画面を、幅375px、768px、1024px、1280pxで実際に表示して、崩れがないかを確かめる。

### あなたにお願いする実機の確認(iPad / iPhone)

1. ホーム画面から起動して、standalone表示になる
2. 下部のタブと選択バーが、ホームインジケータと重ならない
3. 横向きでも崩れない
4. 行全体をタップして選択できる。「⋯」から編集・複製・削除ができ、削除は確認が出る
5. 検索欄でひらがなを入力して、漢字に変換できる(バーとキーボードの重なりも確認)
6. ルートを開いてから戻ると、次に開くルートが目立っている
7. 更新のあとも、これまでに登録した訪問先がそのまま残っている

## 11. スコープ外

ドラッグ&ドロップでの並べ替え、Apple Mapsの追加、複数端末での運用(別ブランチ)、ダークモード、多言語対応。

## 12. リスク

- iPadのSafariでの見た目や、固定バーとキーボードの重なりは、実機でないと確認できない(§10の実機確認で補う)。
- 画面の作り直しなので、既存のテストの書き換え量が大きい。既存の振る舞いを守るため、テストは削らず、新しい構造に合わせて書き直す。
- 名前の変更は、すでにホーム画面に追加済みの端末には、追加し直すまで反映されない。
