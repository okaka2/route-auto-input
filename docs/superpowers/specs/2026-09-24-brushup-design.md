# ブラッシュアップ設計書(基本版で試運転)

作成日: 2026-09-24
状態: 設計確定・実装前
対象: route-auto-input(基本版)。問題なければ CSV版 → 薬局版 の順に取り込む。

## 0. 目的と範囲

訪問の仕事で毎日使える使い勝手に引き上げ、有料版の目玉となる機能(位置の登録・駐車情報・メモ・写真)を基本版で試運転する。
お試し版/有料版の作り分け・ライセンスコード・件数の制限は**今回入れない**。

段階ごとに公開して実機で試運転し、問題なければ次の段階へ進む。

| 段階 | 内容 |
|---|---|
| 1 | スタイルチェンジ(ダークモード対応)、データを守る仕組み、一覧・登録・設定の改善 |
| 2 | 出発地・帰着地、履歴から選ぶ、訪問済みと時刻 |
| 3 | 位置の登録、駐車情報・メモ・写真、お役立ち地点 |
| 4 | 引き継ぎ・配布(パスワード付き) |

守るもの: 既存のテスト(413件)と文言の禁止語テスト、TDD、`src/` の構成(state / views / db の分離)、データは端末の中だけ(サーバーなし)。

## 1. 見た目(段階1)

### 1.1 色
- 条件: 強い日差しの下でも、夜の車内でも読める。
- 明るい画面: 白地(`#ffffff`)/本文は黒に近い色(`#1a1d21`)。薄いグレーの文字(`--muted`)も `#4a5058` 程度まで濃くする。
- 暗い画面: 黒に近い地(`#121416`)、面は `#1c2024`、文字は落とした白(`#e6e8ea`)。
- 基調は深い緑(明るい画面 `#1e6b58` / 暗い画面 `#4fb08f`)。ボタンは色だけに頼らず枠線を付ける。
- 文字と背景の差は全部品で 4.5:1 以上(24px以上の見出しは 3:1 以上)。
- 実装: `styles.css` の `:root` の変数を、`prefers-color-scheme: dark` と `:root[data-theme="dark"]` で上書き。`color-scheme` も切り替える。

### 1.2 切り替え
- 既定は「自動」(OSに連動)。設定に「表示: 自動/明るい/暗い」。選択は `localStorage` に保存し、起動時に `<html data-theme>` へ反映(`prefers-color-scheme` の変化も監視)。

### 1.3 画面の整理
- 一覧の上: 1行目「履歴から選ぶ」「＋登録」、2行目「検索」「並び替え」+小さな「全選択/全解除」。
- 一覧の直上に「すべて N/選択中 N」の切り替え。
- 文字: 本文 16px 以上、訪問先の名前 18px。
- 下の ①②③ ステップの帯は残す。

## 2. データを守る仕組み(段階1)

- 表示の優先順位: ホーム画面への追加 > バックアップのお知らせ。同時に1つだけ一覧の上に出す。
- **ホーム画面への追加の案内**: `display-mode: standalone` でないときだけ。Android(`beforeinstallprompt` が来たとき)は「ホーム画面に追加」ボタン、iPhone/PC は手順(端末判定は `platform.ts`)。「閉じる」で 7日間は非表示(`localStorage`)。
- **「消さないで」**: 初めて訪問先を保存した直後に `navigator.storage.persist()` を1回。結果を設定の「データの保存: 保護されています/通常」に表示(`navigator.storage.persisted()`)。
- **バックアップのお知らせ**: `meta` に最後の書き出し日時。未書き出しで 5件以上、または 30日経過で表示。「あとで」で 7日後。書き出し成功で日時を更新し、設定に「最後のバックアップ: 9月20日(4日前)」。

## 3. 一覧・登録・設定の改善(段階1)

### 3.1 一覧
- `AppState.listFilter: 'all' | 'selected'`。「選択中」表示中は帯「選択中の N人を表示しています [すべてに戻る]」。
- 「選択中」表示中にチェックを外した行は、その表示中は薄く残す(`recentlyUnselectedIds`、画面遷移や切り替えでクリア)。
- 検索は現在の表示範囲の中で。選択中で見つからなければ「[すべてから探す]」。
- 誰も選んでいなければ「選択中」は無効。下の選択バーの「N件選択中」を押すと「選択中」へ。
- `MAX_SELECTION` を 30 に。訪問順の画面で `splitIntoRoutes` の区切りに「── ここからルート2 ──」。
- 訪問順の各行に「⋯」→「先頭へ」「最後へ」(`state.ts` に `moveToTop/moveToBottom`)。

### 3.2 登録・編集
- `Patient` に `phone?: string` を追加(任意)。一覧の行とルートのカードに `tel:` リンク。
- 新規のときだけ「保存して続けて登録」を入力欄の直下に。保存後は名前・住所・電話を空にし名前へフォーカス、上に「○様を登録しました(続けて N人目)」。
- 同じ人の知らせ: 保存時に `findSimilar(patients, input)` で同じ住所または同じ名前を検出(編集中の自分は除く)。ダイアログ「そのまま登録/登録済みを開く/戻って直す」。
- 正規化(`normalize.ts`): 空白除去、全角→半角(英数・記号)、ハイフン類(‐ - − ー ―)統一、「N丁目M番K号」→「N-M-K」、末尾の「様/さん」除去。建物名・部屋番号が違えば別扱い(正規化した住所の完全一致で判定)。

### 3.3 設定の画面
- 文言: 「書き出す」「読み込む」「バックアップのファイル」。
- 並び: ①出発地・帰着地 ②バックアップ ③データの保存状態(保護/通常、履歴をすべて消す) ④表示(自動/明るい/暗い) ⑤このアプリについて。
- (CSV版で ラベル・名簿の取り込み を②の前に追加)

## 4. ルートの改善(段階2)

### 4.1 出発地・帰着地
- `meta.office: { name, address, location? }`(設定で登録)。
- `meta.routeEnds: { start: 'office' | 'current' | 'first', end: 'office' | 'last' }`。訪問順の画面の上で選ぶ。前回の選び方を保持。
- `buildGoogleMapsUrl` の拡張: `origin`(住所 or 緯度経度 or 省略=現在地)、`destination`、`waypoints`。ルートが分かれるときは、1本目だけ origin を出発地に、最後の1本だけ destination を帰着地に。途中のルートは前のルートの最後の訪問先を origin にする。
- 1ルートの訪問先の上限 = `MAX_STOPS_PER_ROUTE` − (出発地・帰着地で使う地点数)。画面に「訪問先は1ルート8件まで」を表示。
- 共有(LINE)は現状どおり受け取る人の現在地から(出発地は送らない)。

### 4.2 履歴から選ぶ
- 新しいストア `history`: `{ date: 'YYYY-MM-DD', ids: string[], routeEnds, visited: { [id]: ISO8601 } }`。「地図を開く」を押したときに当日分を上書き保存。
- 一覧の一番上に「履歴から選ぶ」と近道「先週の○曜日と同じ(N人)」(7日前の記録があるときだけ)。
- 履歴の画面(`screen: 'history'`): 日付・曜日・人数・名前の先頭3人。曜日で絞り込み。行を開くと全員と順番、「この人たちを選ぶ」で `selectedIds` と `routeEnds` を復元。名簿にない id は飛ばして「N人は名簿にないため選べませんでした」。
- 8週間より古い記録は起動時に削除。設定に「履歴をすべて消す」。

### 4.3 訪問済みと時刻
- ルートのカードの各訪問先に小さな「済」。押すと `history[today].visited[id] = now`、もう一度で削除。
- 履歴の画面の各日に「9:12 山田様 → 10:05 佐藤様 …」と「コピー」ボタン。

## 5. 目玉の機能(段階3)

### 5.1 位置の登録
- `Patient.location?: { lat, lng, accuracy, recordedAt, source: 'gps' | 'paste' }`。
- 入口: ルートのカード(未登録のときだけピンのボタン、44px)と一覧の「⋯」(登録/やり直し/消す)。
- 「今いる場所で登録」: `watchPosition` で最長 10秒、誤差を表示。20m 以内で「登録できます」を有効化(それ以上でも登録は可能)。50m 以上なら「車の外や屋外でもう一度」。
- 登録後「登録しました [地図で確かめる]」+数秒間「元に戻す」。
- 貼り付け欄(`locationParse.ts`): 「35.68, 139.76」形式、Googleマップの長いURL(`@lat,lng` / `!3dlat!4dlng` / `q=lat,lng`)。短いURLは案内文のみ。
- 未登録の表示: 一覧に「位置 未登録」、ルートに「位置が未登録: N件」。
- `buildGoogleMapsUrl` へ渡す地点は「位置があれば `lat,lng`、なければ住所」(共有も同じ)。

### 5.2 駐車情報・メモ・写真
- `Patient.parking?: { type: 'onsite' | 'coin' | 'street_permit' | 'management_ok' | 'unknown', permitExpires?: 'YYYY-MM-DD' }`。
- `Patient.note?: string`。見出しボタン(駐車場・入口・インターホン・鍵・注意)は「駐車場: 」等の文字を挿入するだけ。
- 写真は別ストア `photos`: `{ id, patientId, blob, createdAt }`。1件 3枚まで。`<input type="file" accept="image/*" capture="environment">`。Canvas で長辺 1280px・JPEG 品質 0.8 に縮小(Exif はこの過程で落ちる)。
- ルートのカード: 駐車のアイコン+短い文字、メモは「駐車場」「入口」の行を優先して 1行、写真は枚数→押すと拡大(左右にめくる)。
- 許可証の期限: 30日前から一覧の上に「許可証の期限が近い: N件」。
- 書き出し: 「□写真も含める(約○MB)」(既定オン)。写真は base64 で同じ JSON に入れる。写真なしのファイルを読み込んでも既存の写真は残す。

### 5.3 お役立ち地点
- ストア `spots`: `{ id, kind: 'toilet' | 'rest' | 'store' | 'parking' | 'other', note, location, createdAt }`。
- 登録は「今いる場所で登録」。地図を開く画面で、位置登録済みの訪問先から 500m 以内(ハバースイン)の地点を表示。押すと Googleマップで開く。バックアップに含める。

### 5.4 軽さ
- 位置の処理・写真の縮小・暗号(段階4)は `import()` で使うときだけ読み込む。
- 写真は一覧の描画に載せない(枚数だけ)。

## 6. 引き継ぎ・配布(段階4)

- 入口: 一覧の「⋯」→「この訪問先を送る」、複数選択時は選択バーの「選んだ人を送る」、設定の「お役立ち地点を送る」。
- 中身: 選んだ訪問先(名前・住所・電話・位置・駐車・メモ・写真=含めるか選択)+お役立ち地点(任意)。
- 送る前に「名前・住所・写真が相手に渡ります」を確認。
- パスワード必須(6文字以上)。`meta.sharedSecret` に「事業所の合言葉」を保存でき、送受信で自動使用。「パスワードは LINE とは別の方法で伝えてください」を表示。
- 暗号(`crypto.ts`): PBKDF2(SHA-256, 200,000回, salt 16B) → AES-GCM(iv 12B)。ファイルは `{ v:1, salt, iv, data }` の JSON、拡張子 `.hrv`。Web Share(files)→ 使えなければダウンロード。
- 受け取り: 設定の「読み込む」でファイルを選ぶ、または共有で受け取ったファイルを開く。パスワード違いは何度でも再入力。忘れたら開けない旨を明記。「山田様ほか2人を名簿に追加しますか?」→ 同じ人(正規化した名前+住所の一致)は1人ずつ「上書き/別に追加/やめる」。
- 既存の暗号なしバックアップは自分用として残す。

## 7. データの保存(db.ts)

- DB バージョンを上げ、`onupgradeneeded` で `history`・`photos`・`spots`・`meta` のストアを追加。`patients` の新フィールドは任意項目のため既存データはそのまま使える。
- `meta` はキー・バリュー(office / routeEnds / lastBackupAt / sharedSecret など)。
- バックアップの JSON は `version` を 2 に上げ、`patients`・`photos`(任意)・`spots`・`meta(office, routeEnds)` を含む。旧形式(version 1)も読める。

## 8. テストと確かめ方

- 純粋な関数(正規化・類似判定・URL生成・ルート分割・履歴の絞り込み・座標の解析・距離・暗号の往復)は Vitest で先に書く。
- 画面は既存どおり jsdom で描画し、文言テスト(禁止語)に新画面を追加。
- ブラウザ依存(位置・カメラ・Web Share・`storage.persist`・`beforeinstallprompt`)は呼び出しを薄い層(`platform.ts` / `geo.ts` / `share.ts`)にまとめ、テストでは差し替える。
- 実機で確かめる項目を段階ごとに `docs/superpowers/plans` の計画に一覧化(iPhone Safari / ホーム画面追加 / Android Chrome / PC Chrome・Edge、明るい・暗い画面、位置の誤差表示、写真の縮小、LINE 共有、ファイルの受け取り)。
- 各段階の終わりに `npm test` と `npm run build` を通し、`dist` の JS が目安 120KB(gzip 前)を超えないことを確認。

## 9. CSV版・薬局版への取り込み

- 基本版で段階4まで問題なければ、コミット単位で CSV版へ cherry-pick。CSV版では追加で「ラベルでまとめて選ぶ」「名簿の取り込みの汎用化(見出しの拡張・列を選ぶ・貼り付け・ラベル列)」「ラベルの名前の変更・並び順」を設計・実装。
- 薬局版は CSV版から取り込む(初期ラベル・アプリ名・合言葉は各版のまま)。
